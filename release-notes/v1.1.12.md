## v1.1.12

### Fixed
- **The SD card only worked before the touchscreen was initialised.** SD and touch share
  VSPI on different pins (card 18/19/23, touch 25/39/32), and `SPIClass::begin()` does
  nothing once the bus has been started — so after `touchInit()` re-muxed the bus, every
  later `SD.begin()` kept talking to the touch pins and failed silently. The price cache, the
  per-coin chart cache and `/batt.csv` never reached the card; only the boot reads
  (`wifi.txt`, `apikey.txt`, `pages.txt`), which happen before touch init, worked. Both now
  share one `SPIClass` that ends and re-attaches its pins per device.
- **"Loading data..." with the card out.** The sparkline request is ~80 KB and
  `HTTPClient::getString()` returned that chunked body truncated, so every parse failed with
  `IncompleteInput`. The SD cache had been hiding it. Prices now go first in one ~17 KB
  request, then sparklines in small batches.
- **A boot that missed WiFi stayed offline.** `setup()` waited 12 s once and nothing ever
  re-checked `WiFi.status()`. The link is now watched every 10 s, the driver is nudged while
  down, SNTP starts when it comes up, and a fetch runs immediately on reconnect.
- **A rejected API key blanked the screen.** A 401/403 now drops the key for the session and
  retries anonymously, and a key that does not start with `CG-` is called out at boot.
- **"WiFi failed!"** no longer appears when the link comes up a few seconds later; it waits
  20 s and says "WiFi not up yet - retrying...".

### New
- **`/batt.csv`** on the SD card, one line a minute: epoch, uptime, raw pin mV, cell voltage
  before and after sag compensation, percentage and WiFi state. Now that SD writes work, the
  discharge curve can finally be captured.

### Changed
- **Sparkline batches cover five coins** and the standalone price request is skipped when
  every coin already has one. A 19-coin refresh is four calls instead of six.
- **The cache write reports itself.** Mount, mkdir, open and write failures print to serial,
  and the first successful creation logs `cache: created /cache/btc.bin (…)`.

### Verified on hardware
2-USB CYD: page 1 live with all four sparklines, `/cache/btc.bin` written (19 coins, 168
points each), chart cache files on the card, `/batt.csv` growing, and touch still working
after the bus change. WiFi supervision recovered a boot whose association had timed out.

### Known limits
- Anonymous CoinGecko allows ~5 calls/minute, so a sparkline batch can still 429; those
  coins show prices without a graph. A CoinGecko demo key in `apikey.txt` (`CG-…`) raises the
  limit to ~30/min. Streaming the sparkline response (one request, no size cliff) is the
  planned fix.
- The battery curve and divider constant still want a discharge capture on a 1-USB board.

**Bins:** `CYD-Crypto-Tracker-1usb.bin` (ESP32-32E) · `CYD-Crypto-Tracker-2usb.bin` (2-USB
variants), with `SHA256SUMS.txt` alongside them.
